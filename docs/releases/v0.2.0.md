# Herdr Phone v0.2.0

Herdr Phone v0.2.0 replaces the terminal-first phone interface with an
agent-first control plane. The default screen is now an attention inbox for live
agent runs; the terminal remains available as a full-fidelity recovery surface.

## Highlights

- New shadcn-based Dispatch Log interface with Public Sans, IBM Plex Mono,
  contrast-checked light and dark themes, phone safe areas, 200% text zoom, and
  stable phone/tablet/desktop layouts.
- Agents inbox grouped by Needs you, Working, Updated, Idle, and Status unknown.
- Run detail with exact execution context, local instruction history, observed
  lifecycle changes, honest recent terminal output, and one-tap console access.
- Resumable Start run flow for existing workspaces, new workspaces, and linked
  worktrees, with explicit partial-success recovery.
- Workspace-first management for linked checkouts, tabs, panes, agent startup,
  layout controls, and confirmed destructive actions.
- Lazy-loaded xterm.js console with generation-preserving reconnect, pane
  replacement detection, logical mobile keys, and confirmation-bound takeover.

## Relay and security

- Added a versioned `GET /api/v1/runs` contract and generation-guarded run detail
  endpoint. The relay publishes identity, context, status, capabilities, and one
  bounded `observed_terminal_output` part.
- Terminal output is never presented as an assistant message, tool call,
  approval, diff, or test result. Older relays fail closed to snapshot plus
  `pane.read` by capability.
- Run content is memory-only, `Cache-Control: no-store`, excluded from the
  service-worker cache, and absent from logs and audit records.
- Request-id replay is now bound to operation, generation, and canonical params.
  Reusing an ID for a different payload is rejected.
- Upstream failure categories retain safe static error codes without forwarding
  potentially sensitive Herdr messages.
- Every pane and agent mutation now carries the canonical pane ID and current
  nonzero lifecycle generation. The production mock enforces the same contract.
- Uncertain instruction delivery is never retried automatically, including the
  first instruction in Start run.

## Breaking changes

- The terminal-first `/terminal`, `/herd`, and `/spaces` routes were removed.
  `/` now opens the Agents inbox; use `/runs/:runId`, `/workspaces`, and
  `/console/:paneId` for the corresponding new surfaces.
- Run IDs are opaque and include pane generation plus agent incarnation. Old run
  bookmarks safely resolve as ended rather than attaching to a replacement.
- Worktree provenance now comes from `workspaces[].worktree`, matching Herdr
  v0.7.5. The phantom top-level worktree array was removed from the browser wire
  model and mock.
- The PWA and relay are released as one embedded artifact. Do not serve a v0.1
  frontend from a v0.2 relay.

## Verification

The release branch passed:

- `make check`, including Go race tests, an 80% coverage floor, 324 frontend
  tests, production frontend embedding, and install smoke tests.
- 159 Playwright journeys across Pixel 7 Chromium, iPhone 15 WebKit, and desktop
  Chromium with one worker and zero retries.
- Repeated WebKit stress of Start run and repeated full Vitest runs after fixing
  the discovered scheduling races.
- `make verify-plugin` against checksum-pinned official Herdr v0.7.5.
- `govulncheck ./cmd/... ./internal/...` with zero reachable vulnerabilities.

`npm audit` reports high-severity advisories in the development-only
ESLint/Workbox build graph and React Router's unused RSC server mode. Herdr Phone
ships a client-only SPA embedded in a Go relay and includes neither vulnerable
runtime path; upgrading those dependency families requires separate breaking
dependency work.

See [`docs/design/agent-first-ui.md`](../design/agent-first-ui.md) for the full
product and architecture assessment.
